# P06 冷源群控工程交付说明

## 交付状态

基于用户提供的 CHP01-P05.ZEF 和 SMCL-P05.ZEF，保留其 Control Expert V16.2、DTDVersion 41 的工程交换结构，重写核心启停、保护、调度与恢复逻辑。交付文件为：

- `CHP01-P06.ZEF`：M340 单机控制工程，仍为 UNIT_NO=1。
- `SMCL-P06.ZEF`：M580 热备群控工程，仍按原五台机组配置。
- `CHP01-source.xml`、`SMCL-source.xml`：工程包内部 XML 的可审阅副本，不是另行验证过的独立 XEF 导入文件。
- `sources/`：工程中 ST 程序段的文本副本。
- `variables.json`：新增变量的名字、类型和定位地址。
- `checksums.json`：输入原工程及输出工程的 SHA-256。
- `validation-behavior.txt`、`validation-structure.json`：主机侧行为测试、结构检查结果。
- `tools/build_zef.py`：根据原始 ZEF 重复构建交付文件；原始工程不包含在交付目录中。

**这是离线重写、待导入编译的工程源码版本，不是已编译或已投运版本。** props.xml 的 `AppBuilt` 已设为 FALSE，避免沿用原文件的已构建标志。当前环境没有 Control Expert，未执行其导入、编译、目标 CPU 仿真、热备切换或现场联动。

未修改原始上传文件，也未自动上传 GitHub。请保留现场已投运工程作为独立备份，不要直接用本版本覆盖运行系统。

保留原硬件 IOConf、commParameters、已有变量名字/类型/定位地址、DTM 及其他非源码归档成员、现有 DFB 类型、SCADA 数组映射。归档中除 unitpro.xef 和 props.xml 外的成员按原字节保留。

不重新设计原蓄冷阀组的工艺含义、露点计算、差压 PI、模拟量量程及厂家 RTU 点表。以提供的工程接口为依据；不能推断现场 P&ID 或缺失的厂家接口。

## 单机顺控

| P06_State | 含义 |
|---|---|
| 0 | 停机等待，检查许可和最小停机时间 |
| 10 | 开原工艺要求的阀组，等待实际位置 |
| 20 | 启泵并等待有效、连续稳定的水流 |
| 30 | 发冷机运行命令，等待实际运行反馈 |
| 40 | 运行，持续检查水路/故障 |
| 50 | 撤冷机命令，等待冷机实际停止 |
| 60 | 水系统后运行，必要时维持有用的蓄冷放冷 |
| 70 | 撤泵命令并确认泵停止 |
| 80 | 停止完成的过渡状态 |
| 900 | 故障锁定，安全静止后按新复位边沿恢复 |

新增最终保护段位于 Drive_OP 之后：软件手动命令也不能绕过当前泵、水流、必要水路、供电、维护和冷机故障条件。水流值坏质量时，不允许拿保持的历史正常值作为水流证明。当前水流证明丢失会立即抑制冷机物理运行输出；持续 2 秒后形成顺控锁定故障。

维护请求先停冷机、确认反馈、完成必要水系统后运行，实际冷机和泵均停且状态安全后才允许关闭隔离阀。启动和停止不可在中途直接反向；重新使能要等完整停机及最小停机时间。

冷机停止超时保持在 50 并报警，不会因计时到期擅自停水。单机冷机故障而水路/泵健康时，若原蓄冷逻辑进入放冷、蓄冷容量仍有效且群控仍使能本机，状态 60 维持放冷供水；替换机交接撤使能后再完成停泵。泵、水路、维护、容量不足等条件仍优先，不用“等替换”覆盖本机保护。

新增故障码：1 参数错误；2 设备/水路相关故障；3 持续水流证明丢失；4 运行反馈丢失；10 开阀超时；20 建立水流超时；30 冷机拒启超时；50 冷机停止超时；51 停止过程中冷机非预期重新运行；70 泵停止超时；99 非法状态。

## 时间策略及与 P05 的重要差异

| 条件 | P06 示例值 |
|---|---|
| 正常最小停机 / 最小运行 | 10 / 10 分钟，由真实冷机反馈计时 |
| 开阀上限 | 120 秒 |
| 建立水流上限 | 原 START_LOWFL_TM，默认 120 秒 |
| 连续水流建立 | 10 秒 |
| 冷机拒启上限 | 180 秒，独立于温度偏差报警 |
| 冷机停机反馈上限 | 180 秒，仅报警、不越级停泵 |
| 停机后水系统延时 | 原 STOP_PUMP_DELAY，默认 120 秒 |
| 相邻群控启动间隔 | 120 秒；每次启动显式复位计时器 |
| 群控启动事务上限 / 停止事务报警 | 10 / 15 分钟 |
| 轮换连续交接时间 | 原 HANDOVER_TM，默认 120 秒 |
| 整次轮换上限 | 20 分钟 |

这些是审阅用默认值，必须与厂家要求、ATS/UPS、蓄冷维持时间、供电和水力设计一起确认。`System_ENA=FALSE` 为正常有序停止，不等同急停；状态未知的机组不能由软件假定已经停止。

**快速重启不是默认绕过防短循环。** 新变量 `P06_FastRestartApproved` 默认 FALSE；只有厂家明确支持此快速重启策略后，才可将它配置为 TRUE。此时仅针对捕获的运行中失电事件，最小停机时间可为 120 秒，其他故障、当前水路、后运行和复位条件不被绕过。普通停机仍为 10 分钟。原 SMCL `PWR_RESTART_TM` 保留兼容，但不再直接控制新的单机防短循环状态；不能仅改旧 HMI 参数就认为启用了快速重启。

## 通信扩展与部署约束

沿用原 20 字命令块、30 字反馈块，利用保留字，不改变块长度。

| 字段 | 用途 |
|---|---|
| 单机反馈偏移 +24 | INT 版本标识 2606；CHP01 为 %MW724，SMCL 第一台为 %MW424，其余按原 30 字间隔 |
| 单机反馈偏移 +25 bit0 | 顺控故障锁定 |
| bit1 | 当前允许启动，含最小停机时间、模式及实际停机条件 |
| bit2 | 当前允许正常停机，含最小运行时间 |
| bit3 | 至少一路本机出水温度有效 |
| bit4 | 停机/停泵超时故障 |
| bit5 | 水处理到期、申请启动 |
| bit6 | 本机 LOCAL_EN，就地控制权 |
| 群控命令 word1 bit6 | 本机水处理启动的唯一授权；原 bit0..5 保留含义 |

上报温度改为只选择有效温度通道；单路有效时两格均发送该有效值；两路都失效时保持读数但明确清除质量位，不能用于交接。

群控冷/热启动先逐机等待新的心跳和正确版本，再从本机 ACH_EN 回显接管。恢复窗口超时只结束全局等待，不会把没收到状态的机组写成 OFF；未接管机组的命令有效位保持为 0。通信恢复后逐机接管，恢复后不立即减掉新接管的运行机组。

**必须成套升级参与自动调度的单机。** 本次只提供用户上传的第 1 台工程；其余四台应按本机模板移植相同逻辑和协议，保留各自硬件、机号和地址，并分别编译验证。不能把 CHP01 的网络/IO 配置原样下载到其他控制器。未经升级的旧单机保持“待接管”，不会被新群控当成就绪备用机使用。不能在满负荷运行时直接混用 P05/P06 完成切换。

水处理由 SMCL 单点授权；任何配置内机组未知或失联时，暂停新的水处理启动授权，避免失联机组可能仍在水处理而重复启动。已经进入周期的本机可按原逻辑完成，保护和运行需求可中止。

## 参数、告警与未完成接口

- 新变量全部以 P06_ 开头。新增故障加入原 `ALM_UNIT_ANY` / `GEN_ALM` 汇总；未新增 SCADA 独立点地址或画面，详细状态需在 Control Expert 变量表或后续 HMI 设计中显示。
- 原 HMI 的 `PWR_LOST` 继续显示已使能机组的实际失电状态，`RESTART_FAIL` 对应新的启动禁止锁定，`ROT_DONE_MSG` 显示选择的替换机号；不再把旧的失电等待计时逻辑当作启停保护的唯一依据。
- `P06_BMS_LOAD_VALID` 默认 FALSE，禁止未验证的服务器负荷参与加机。需接入真实 BMS 数据新鲜度/通信质量后再使用；其他温度、压差/速度及有效水侧负荷条件仍按原 SOO 工作。
- 组态修改仅在停机维护条件下执行。部分旧 HMI 参数仍直接沿用原工程写入流程；本交付不代表所有旧参数、模拟量量程和厂家表项都已完成现场合理性验证。
- 原工程中蓄冷罐/伴热 RTU 表未完成、冷机远程状态软件占位等未有新资料，仍需厂家点表确认，不能伪造寄存器来补齐。
- 只修正备用通信选择的明显软件端点/有效性路径，不证明 M580 热备、双网、交换机、扫描器和主备控制权已验证。必须做断网、切主、两 CPU 重启、单向通信故障的 FAT。

## 导入、验证与现场验收

1. 在隔离的 Control Expert V16.2 工作目录中，通过软件支持的打开/导入工程交换功能打开新的 ZEF；保留 P05 和现场已投运备份。
2. 执行工程分析与完整重新生成，核对 CPU、固件、DTM、库版本、数据区/扫描周期容量、Section 顺序及新增变量。
3. 特别确认 `P06_FINAL_GUARD` 在 Drive_OP 后、物理输出刷新前执行；不能把它跳过或移至驱动块之前。
4. 逐项核对点表、模拟量实际量程、阀门回路、流量阈值、联锁及供电状态来源；确认 `%S0/%S1/%S6` 在目标 CPU 和热备任务中的实际行为。
5. 完成五台单机的对应移植和通信扩展，再做群控离线仿真。不要为了通过联动而伪造版本或就绪位。
6. FAT 至少包括：正常分级启停；每一步拒动；运行丢流/泵故障；温度坏质量；启动/停机反馈卡住；运行中维护；轮换新机失败/旧机故障；蓄冷放冷至容量不足；群控全停/热备切换；单向通信故障；UPS 保持与二次失电；厂家确认后的快速重启。
7. 按批准的现场调试流程分台、分阶段接入设备。厂家压缩机、蒸发器、低流量及独立急停保护继续有效，本程序不能替代。
