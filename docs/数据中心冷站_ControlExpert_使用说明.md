# 数据中心冷站加减机模板（Control Expert / M580、M340）

本模板是可供工程设计、审查和仿真使用的 ST 参考源码，包含需求计算、群控调度、单机水系统顺控和四机调用示例。**不是可以直接导入的 XDB/XEF 工程，也未经施耐德编译器或真实 PLC 验证。** DDT、DFB 需按下面步骤在实际 Control Expert 版本中建立并编译，再进行 FAT/SAT。所有时间和温度默认值仅用于说明，必须按冷机厂家、液压设计、供电容量和现场控制要求确定。

## 1. 适用边界

- 默认四台**等制冷量的水冷冷机**，三用一备；最多支持 16 台。
- 每台冷机有独立的冷冻水泵、冷却水泵、蒸发器/冷凝器隔离阀，以及独立的冷却塔控制请求。阀门开到位、关到位分别为本机两侧阀门的组合证明。
- 冷却塔的风机变频、低温防冻、水位、风机轮换由冷却塔控制器处理；`TowerReadyFb` 是其“可提供冷却条件”证明，不等同于某个风机必须运转。
- `EnableLoad` 是厂家支持的加载许可，`LoadedFb` 是实际制冷能力/运行就绪证明。厂家的数字接口、Modbus/BACnet 点位、脉冲启停、容量限幅和卸载确认需要通过独立适配层实现。**不能用输出命令回读代替反馈。** 如果厂家没有独立加载/卸载接口，应依据实际协议调整顺控，而不是虚构反馈。
- 共用一次泵、一次二次泵、变流量一次泵、共用冷却塔、双路冷源和跨机房灾备，不得直接把这套独立机组输出并接到共用设备。须增加公共设备调度层，按当前需求和运行机组数建立流量/压差/冷却能力证明，再连接本模板的许可。不同容量设备须改为制冷量调度，不能只按台数分配。
- 冷机本体的防喘振、压缩机保护、蒸发器最小流量、冷凝器保护、制冷剂保护及安全回路由厂家控制器和独立保护实现；群控不能替代这些保护。

## 2. 文件与工程建立

| 文件 | 作用 |
|---|---|
| `examples/datacenter_control_expert/01_Types.st` | DDT 和固定 1..16 下标数组 |
| `02_FB_DC_Train.st` | 单台冷机及专用水设备的 DFB |
| `03_FB_DC_Plant.st` | 需求台数、备用机选择、故障补机、轮换、恢复调度 |
| `04_FB_DC_Demand.st` | 可选的供水温度加减机调节器 |
| `05_PRG_DC_Example.st` | 四台机组、三用一备的完整调用和 I/O 软件映像示例 |
| `tests/datacenter_control_expert/` | 主机侧 ST 子集扫描验证器与自动场景测试 |

建立步骤：

1. 在数据编辑器建立 `01_Types.st` 中的各个 DDT；数组下标必须为 `1..16`，不能改成 `0..15`。
2. 分别建立 `FB_DC_Train`、`FB_DC_Plant`、`FB_DC_Demand` 三种 DFB。在各 DFB 编辑器建立 `VAR_INPUT` / `VAR_OUTPUT` 对应接口，`VAR` 对应私有实例变量；各 `TON` 为独立实例，不得共享。
3. 将声明之后、`END_FUNCTION_BLOCK` 之前的正文放入相应 DFB 的 ST Section。`FUNCTION_BLOCK`、`VAR_*` 和 `PROGRAM` 是参考文件的声明容器，不要把整个文件粘贴进 ST Section。
4. 依照源码设置输入默认值。若当前版本的 DFB 接口不接受声明初始化，就在数据编辑器设置初始值，或在调用处显式传入所有配置参数。变量类型、DFB 数组/结构接口和调用形式以所用 Control Expert 版本的编译结果为准；示例避免使用 DFB 实例数组。
5. 参照 `05_PRG_DC_Example.st` 建立应用变量和周期性 MAST ST 段。四个单机 DFB **先调用**，再计算需求，**最后调用**群控 DFB；请求在下一扫描周期生效。每个实例每周期只调用一次。
6. I/O 输入映像及通信质量先更新，再执行本段，最后由唯一的输出适配层写实际命令。HMI 不能与本 DFB 同时写设备输出。
7. `ColdOrWarmStart` 必须覆盖冷启动和热启动。一般可结合平台 `%S0` / `%S1` 启动位和本应用初始化逻辑生成单扫描脉冲，须核对 CPU/冗余配置的系统位定义；不能只依赖一个可能在热启动时保留的 `InitDone`。冗余切换也须单独验证实例、定时器和命令所有权。
8. 群控请求、状态机、边沿记忆和定时器禁止作为历史命令恢复。运行小时数由真实运行反馈计时、保存在独立保持型小时计中，或读自设备/BMS；把它们转换为非负、有效的 `RunHours[1..4]`。模板不负责维护小时计。

参数只能在停机和受控维护条件下修改。运行中改变 `UnitCount`、设备映射、保护时间或容量上限不属于本模板支持的操作。

## 3. 逻辑分层

### 需求层：FB_DC_Demand

- 供水温度持续高于 `Setpoint + AddBand`，且已有需求已兑现、无机组切换时，加一台。
- 温度持续低于 `Setpoint - ShedBand` 时减一台；默认最少一台。
- 每次改变台数后等待 `SettleTime`，并等待实际加载台数等于需求；避免启动过程中需求一路累加至上限。
- 温度越界、NaN 或传感器质量失效时，冻结需求并输出 `DemandValid=FALSE`，群控冻结目标台数，不能把传感器故障当作零负荷。
- 冻结目标不等于停止故障补机：即使温度信号故障，仍可补足上一次有效目标台数；正常减机和计划轮换暂停。
- 在相同需求下，冷机本体继续控制导叶、压缩机或变频负载。本模板的“加载”是加载许可与就绪确认，不是压缩机的模拟量容量 PID。
- 首次启动以最低运行台数为基线；重启时若已有更多机组真实加载，则采用已加载台数，避免初始化立即减机。
- 可以不用本块，改由 BMS 提供 `Demand` / `DemandValid`。群控的加、减需求确认延时仍生效。两个层次的延时是叠加关系，调试时要一并考虑。

### 调度层：FB_DC_Plant

- `MaxDuty` 是日常最多运行台数，`MaxParallel` 是包括切换重叠期间在内的最大同时占用台数。四机三用一备示例分别为 3、4。若电力或水系统不允许四台并行，就设置为 3；满负荷时将阻止无损轮换，而不是先停原机。
- 启动候选机必须真实就绪并满足最小停机时间；先选累计运行小时最少的机组，同小时按下标优先。
- 正常减机先选累计运行小时最多、已加载且达到最小运行时间的机组。一次只发一个正常减机请求，等待其完整停机水系统顺控结束。
- 每次启动后重新计时 `StartSpacing`，并等待当前启动过程完成，防止并发启动及电流冲击。定时器使用显式复位扫描，避免第二次加机直接复用上一轮 `Q=TRUE`。
- 故障/退出自动的机组撤销运行请求。需求目标保持，补机不重新等待需求增加延时，但仍遵守启动间隔、最小停机时间和并行上限。故障机冷机已经停止、仅在水系统延时运行时，可以补起备用机。
- 轮询/轮换：手动 `RotateNow` 上升沿或累计间隔触发，先启动低小时备用机；只有它**连续真实加载**达到 `RotationOverlap` 且原机可停时，才撤销原机请求。加载反馈中断会重计重叠时间。
- 备用机启动失败或轮换超时，保留原机并报 `RotationFailed`；不采用先停后起的强制轮换。若原机自身故障，则转换成普通故障补机。
- 轮换过程中发生目标变化、测量失效或进入恢复等待，取消尚未完成的替换；已经开始的卸载/停机顺控不会反向强行重启。
- `ReserveUnavailable` 表示当下没有立即可启动的备用机，包含最小停机时间尚未满足的情况；不是“永久无备用”。`CapacityShortage` 为实际加载台数不足的条件，正常启动期间也会出现，HMI 应区分恢复中、启动中和持续缺冷报警。
- 不设强制忽略流量、故障锁定或最小停机时间的“紧急加机”。没有可用备机时输出缺容量条件，应由上层实施温度告警、负荷迁移或其他经过设计的降级措施。

### 单机层：FB_DC_Train

| 状态 | 动作及退出条件 |
|---|---|
| 0 | 停机；满足自动、无故障、许可、关阀证明及最小停机时间后才允许开阀 |
| 10 | 开本机两侧隔离阀；开到位且关到位已消失后继续 |
| 20 | 启动冷冻水泵、冷却水泵；等待两泵运行反馈 |
| 30 | 两侧水流及泵、阀条件连续稳定 |
| 40 | 请求冷却塔控制器，等待冷却就绪和水流稳定 |
| 50 | 启冷机；初始启动必须有当前水流证明 |
| 60 | 等待加载许可、实际冷机运行、稳定水流，发加载许可并等待实际容量证明 |
| 70 | 正常已加载运行；计入有效容量 |
| 80 | 撤加载许可，保持冷机运行命令，等待卸载确认；超时报警后进入停冷机 |
| 90 | 撤冷机命令；必须等实际运行反馈消失，超时只报警，不越过此步停水 |
| 100 | 冷机实际停止后的水系统延时运行 |
| 110 | 停两泵；泵未确认全停时保持阀门开启 |
| 120 | 关阀；真实关到位后回 0 或故障锁定 |
| 900 | 故障锁定；安全静止且实际故障消失后，需要新的复位上升沿 |
| 910 | 本机供电丢失等待；撤命令，供电回来先核对实际反馈并回到安全停机，再参加恢复 |

保护优先级：硬停机/退出远程控制 → 本机供电状态 → 设备及过程保护 → 顺控超时 → 正常需求与轮换。

- `HardTrip` 撤销本机全部命令。消防、急停或断水时是否必须保留某些水泵，须由现场安全设计决定；不能把各种严重程度的故障都直接并成这个输入。
- `RunPermit` 是实际过程运行许可，不是需求台数，也不是供电稳定状态。运行中丢失会退出冷机并锁定故障；停机时未就绪仅禁止启动。
- `PowerAvailable` 是本机真实供电状态。预期失电不新建设备故障锁定，但已有设备故障保留；供电未恢复时不输出任何设备命令。它与群控的灾备恢复许可必须分开。
- 水流丢失延时按厂家要求设置，阀门开证明丢失直接撤冷机命令。冷机故障、泵/水系统故障直接进入停冷机，再按实际反馈处理水系统；不能等待正常最小运行时间。
- 普通启停遵守最小运行时间。故障处理、启动未完成时取消及硬停机不受此限制；厂家内部防频繁启动保护仍必须保留。
- 故障复位要求冷机及两泵全停、阀已关且无矛盾、无加载反馈，故障输入消失、远程许可有效。一直按住复位不能自动重复消故障。
- 所有 `TON` 每扫描调用一次，避免未执行分支的定时器残留。冷/热启动重新建立最小启停时间；不假定设备此前已满足防短循环时间。
- 水流/阀门/接触器反馈必须来自物理状态或有效通信，丢失通信不能简单把所有运行反馈写成 FALSE。失效时撤销 `RunPermit` 并保留可信运行状态/进入设计的故障处理，独立低流量保护必须直接作用于冷机。

## 4. 灾备恢复

这里的灾备指**冷站失电、ATS/UPS/供电切换后的恢复调度**，不包含自动跨站接管或 PLC 主备仲裁。

1. `DisasterActive=TRUE` 或 `InfrastructureReady=FALSE` 锁定群控恢复等待；禁止新加机和正常轮换，保留仍受控且健康的运行机组，避免把灾备事件变成二次停机。
2. 真实失电的机组由各自 `PowerAvailable=FALSE` 撤销命令，进入 910；独立故障和安全保护始终有效。
3. 事件解除，基础设施连续稳定 `RecoveryStable` 后，默认还需要操作员重新按一次 `AckRecovery`。提前按住确认无效；必须在稳定后产生新上升沿。按已批准的现场策略可设置 `AutoRecovery=TRUE`。
4. 机组供电恢复后先清理残留运行反馈、泵和阀状态，再满足 `MinOff`。群控通过常规顺序及 `StartSpacing` 逐台恢复至有效需求，绝不恢复历史输出数组。
5. 有独立设备故障的机组不会因灾备恢复自动消故障，必须完成该机真实故障复位。没有可用备机则保留缺容量告警。
6. PLC 重启时，从真实反馈接管仍在运行的健康机组，重建目标；不把初始化 `Target=0` 当作立即减机。已有加载机组不会为了等待首次水流计时而人为撤加载许可。

`Enable=FALSE` 是正常退出自动/有序停机指令，仍按最小运行时间和卸载停水顺序执行；它不是急停。控制权切换或本机转手动须明确由谁持有设备输出，不能让群控和就地逻辑同时驱动。

## 5. 默认参数（必须现场整定）

| 参数 | 示例默认值 | 说明 |
|---|---|---|
| MinOff / MinOn | 10 / 10 分钟 | 冷机实际停、运行反馈计时 |
| ValveTimeout / PumpTimeout | 60 / 30 秒 | 阀门和水泵反馈超时 |
| FlowStable / FlowTimeout | 15 / 90 秒 | 连续水流确认 / 等待上限 |
| FlowLossDelay / CapacityLossDelay | 2 / 10 秒 | 运行丢流 / 容量反馈消失判定 |
| TowerTimeout | 120 秒 | 冷却条件建立 |
| ChillerTimeout / LoadTimeout | 180 / 180 秒 | 冷机启动 / 加载建立 |
| UnloadTimeout / StopTimeout | 120 / 180 秒 | 卸载 / 实际停止 |
| PostRun | 180 秒 | 冷机实际停止后的泵、塔延时 |
| RecoveryStable / StartSpacing | 60 / 120 秒 | 基础设施稳定 / 启动间隔 |
| DemandUpDelay / DemandDownDelay | 60 / 300 秒 | 群控确认外部需求变化 |
| RotationInterval / Overlap / Timeout | 168 小时 / 60 秒 / 30 分钟 | 自动轮换周期 / 连续容量重叠 / 整次切换上限 |
| 供水设定点 / 加机带 / 减机带 | 7.0 / +0.7 / −0.5 °C | 示例温度；按冷站设计修改 |
| 温度加机确认 / 减机确认 / 稳定等待 | 120 / 600 / 600 秒 | 可选温度调节器参数 |

实际 `TIME` 可用范围、定时器精度、周期任务超时和 16 台规模的扫描耗时必须在目标 CPU 上确认。群控不支持带故障的参数继续投入运行；修改配置应进入维护流程。

## 6. 故障码和 HMI

| 故障码 | 含义 |
|---|---|
| 1 | 参数配置错误 |
| 2 | 运行过程许可丢失 |
| 3 / 4 | 冷机本体 / 配套水设备故障 |
| 5 / 6 / 7 | 阀开证明丢失 / 丢水流 / 冷却塔就绪丢失 |
| 8 / 9 / 10 | 冷机运行反馈丢失 / 容量持续消失 / 无运行却有容量反馈 |
| 11 / 12 / 13 / 14 | 阀反馈矛盾 / 硬停 / 运行中远程权丢失 / 非预期启动 |
| 20 / 21 / 22 / 23 | 开阀 / 启泵 / 建立水流 / 建立冷却条件超时 |
| 24 / 25 / 26 | 启冷机 / 建立加载超时 / 加载许可丢失 |
| 27 / 28 | 卸载超时 / 冷机停止超时 |
| 29 / 30 / 31 / 32 | 延时阶段冷机重新运行 / 停泵超时 / 关阀时仍有设备运行 / 关阀超时 |
| 99 | 状态值非法 |

故障码是当前处理故障，不是 SOE 首出故障记录；后续更高优先级或超时故障可能更新它。若需要审计首出故障和事件时间，请在独立报警/SOE 层记录。

HMI 至少显示每台 `State/Fault/FaultCode/Available/Ready/Loaded/ChillerRunning`、加载/停机反馈、最小停机等待和运行小时；群控显示恢复等待、有效目标台数、实际容量、正在启动/停机、无备机、容量不足、轮换中/阻止/失败、需求质量失效和配置错误。`UnloadTimedOut`、`StopTimedOut` 为单机独立保持报警，不能只依靠故障码显示。

## 7. 验证方式和交付边界

仓库提供 `blark==0.8.3` 通用 IEC ST 解析，以及基于其 AST 的主机侧扫描执行器。执行器直接读取 ST 源码正文，覆盖定时器、条件分支、循环、状态机和数组访问；不是另外手写一套群控模型。它不实现完整 IEC 类型系统、CPU 保持语义、PLC 定时精度、真实硬件 I/O 或施耐德 DFB 编译规则。

复现主机侧测试（依赖安装在仓库外）：

```bash
cd /workspace/PLC-ST-Learning
python3 -m pip install --target /tmp/plc-st-validation blark==0.8.3
PYTHONPATH=/tmp/plc-st-validation python3 -m unittest discover -s tests/datacenter_control_expert -v
```

在实际工程必须补做：

| 类别 | 至少验证的现场/FAT 场景 |
|---|---|
| 编译与调用 | 目标 CPU/固件/Control Expert 版本；DDT、DFB、默认值、数组下标、实例私有性；每周期调用次序 |
| 正常启停 | 从零需求、单机到三机；温度正负阈值及抖动；MinOn/MinOff；中途取消启动；正常停机再启 |
