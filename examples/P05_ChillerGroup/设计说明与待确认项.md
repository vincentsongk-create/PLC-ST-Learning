# P05 冷机/水泵群控初稿 V0.1

本交付基于《P05 BMS Design Drawings.pdf》33 页图纸。范围按用户确认：先做冷机/水泵群控；TIA Portal V18、S7-1500 为编写假设。属于可评审源代码初稿，未在 TIA Portal 导入、编译或 PLCSIM 执行，不是可直接下装的项目。

## 图纸依据与边界

| PDF 页码 | 图纸/内容 | 可确认事项 |
|---|---|---|
| 4 | BMS-S00-00-04 | 冷机群控、冗余管理控制器、主管冗余传感器、节能优化的总体目标 |
| 5 | BMS-S00-00-05 | 典型 POD 含 5 台冷机、12 台风墙；优化服务器下发参数；每 POD 两台冗余 PLC |
| 16 | BMS-S01-03-01 | CHPS 单元采用 M340；Modbus TCP 上联，冷机和变频器等采用 Modbus RTU；具体寄存器未给出 |
| 18 | BMS-S02-04-01 | POD-01～06 典型冷冻水图，CHPS001～005；ACH、CHP、TES、CHV1/2/3、CHBPV；供回水及压差传感器 |
| 19 | BMS-S02-04-02 | 网络区图画有 3 套 CHPS；标题典型 POD-09 与适用列表 POD-07/08 存在差异，需澄清 |

原设计为施耐德平台，改用西门子涉及架构和通信移植。本交付不假设 S7-1500 普通 CPU 能实现图纸所述硬件冗余；具体 CPU、冗余系统与远程 I/O 须另行确认。

文件没有提供完整 SOO：未定义加减机判据及持续时间、设计运行/备用台数、容量、温度/压差设定值、泵速控制、TES 充放冷顺序、通信丢失策略和断电恢复顺序。因此以下策略均是待确认的工程初稿，不是图纸已明确规定的动作。

## 文件与功能

- `P05_GroupControl.scl`：两种 PLC 数据类型和群控 FB；最多 5 台，按有效配置数量参与调度。
- `P05_UnitSequence.scl`：单机顺控 FB；将水路建立、泵运行、水流证明、冷机运行分阶段处理。
- `测试与验收清单.md`：待在 TIA/PLCSIM/现场执行的测试场景。

群控采用上游输入 `DemandUnits`，不凭空编造温度、负荷或台数阈值。需求必须来自经评审的 SOO、人工确认的调试需求或后续需求计算 FB。等容量台数模型只是初稿；不同容量机组需改为容量调度。没有假定“4 用 1 备”。

正常增机选可用、自动、停机证明有效且满足最小停机时间的最少运行小时机组；减机选满足最小运行时间的最多运行小时机组。并列时选编号较小者。只在需求变化时均衡，不执行定时在线轮换。正常加减机一次处理一台，并等待阶段间隔。故障锁定的机组不自动反复启动，需健康且完成停机后沿触发复位。

初稿在停机后循环期间不并行启动备用机，停机超时也会阻塞后续调度。因此不满足任何尚未提供的快速恢复时间指标。若项目要求故障后立即投入备用机，必须确认最大并行运行台数、水力影响与功率约束后修改此策略。

单机建议顺序：

`停止 → 建立经确认的水路 → 启泵并确认 → 连续水流证明 → 启冷机并确认 → 制冷运行 → 停冷机并确认 → 泵延时运行 → 停泵并确认 → 关闭水路并确认 → 停止`

水路阶段用 `RouteRequest / RouteReady / RouteClosed` 抽象表达，**未实现** CHV1/2/3、CHBPV 的动作组合。图纸含 TES 及旁通，不能将“全部开阀”当作正确水路。必须补充经评审的水路控制 FB 后才能运行全链路。泵后循环时间、启停超时、水流证明时间均需填写经批准的参数；默认不允许启动。

## 接口映射建议

| 程序接口 | 图纸点位/来源 | 说明 |
|---|---|---|
| 单机 ChillerRequest | ACH-STC/SPC | 维持请求；现场适配成厂家要求的启停协议，不能直接假定为两个反相 DO |
| ChillerRunning / ChillerFault | ACH-S / ACH-F | 应补充独立停止/就绪状态和通信质量；停止证明不能只靠运行位取反 |
| PumpRequest | CHP-STC/SPC | 交给设备接口层，不直接控制接触器 |
| PumpRunning / PumpFault | CHP-S / CHP-F | 需驱动器停止、就绪及质量位 |
| FlowOK | CH-FL 等经确认的本机水流信号 | 图中为流量点，需有效性、量程和厂家最低流量阈值；不能直接 Bool 转换 |
| RouteRequest / Ready / Closed | CHV1/2/3、CHBPV 和相关证明 | 待水路/TES SOO 定义；Closed 为所需安全停止水路状态，不代表所有阀门都必须关闭 |
| RunHours / Available / AutoRemote | 本机控制器/设备通信 | 寄存器、极性和质量均需补齐 |
| CHPVSD-C/FB | 泵变频器 | 本初稿未输出泵速，须由本地控制或后续压差控制 FB 承担 |
| CHWS-T1/T2、CHWR-T1/T2、CHW-DP1/DP2 | 主管传感器 | 本初稿未实现冗余择值、负荷计算及压差 PID，不能冒充已闭环控制 |

冷机温度设定 ACH-TSP、功率 ACH-PW 等尚未映射；群控不直接接收优化服务器写入设备。后续应增加设定值限幅、质量判断、变化率限制、超时回退。

## TIA 导入与调用

1. 新建实际型号的 S7-1500 工程，将两份 `.scl` 文件加入外部源文件。先生成 `P05_GroupControl.scl` 内数据类型和 FB，再生成单机 FB，检查编译诊断。
2. 建立一个群控实例 DB 和每台设备各自的单机实例 DB。使用固定周期 OB 调用；`CycleSeconds` 传入实际间隔秒数，限定大于 0 且不超过 1。周期超限时禁止新写入，由外部看门狗报警。
3. 显式填写全部时限、UnitCount，并在工程评审后设置 `Cfg.Reviewed`、单机 `ConfigReviewed`；它们不是安全认证开关。
4. 将群控 `RequestRun[i]` 送至各单机 FB，单机状态再反馈给群控；允许一周期反馈延迟。群控输出写入单机请求锁存器前，必须检查 `CommandValid AND Unit[i].Installed AND Unit[i].AutoRemote`。无效时保持上次有效请求，不得用 FALSE 替代。
5. 单机输出写入设备接口层时同样检查 `CommandValid`；无效时禁止发送新命令。接口层还须有独立通信看门狗、本地回退及厂家保护，不能无限期依赖保持旧命令。
6. 单机启动初始化仅支持冷机、泵、水路均已证明停止的场景，`InitStopped` 为单周期脉冲。运行中接管、断电后中间状态恢复尚未实现，不得强置反馈来通过初始化。
7. 群控 `Init` 同样为单周期脉冲，仅在所有已安装单元有可靠运行或停止证明时采用状态；它不会清除故障锁。手自动改变后需重新协调再初始化。设备数量、安装标志等配置只允许在计划停机/受控接管时变更。
8. `Authority` 必须来自外部已验证的控制权仲裁。备用 PLC 不得写设备。软件变量无法替代硬件冗余切换、通信冗余及状态同步。

## 明确的限制

- 安全停机、急停、消防、冷机本机低流量/防冻/压力保护由经确认的独立保护承担。本普通 SCL 初稿没有安全完整性等级声明。
- 通信无效、需求无效、控制权丢失时停止发新命令；当前请求保持。本地设备如何持续供冷或安全停机必须由正式 SOO 明确。
- 群控任何已安装机组通信失效会阻止全部新调度，这是暂定保守策略，可能影响备用机投入，须按连续供冷目标评审。
- 本地手动运行机组可按有效制冷证明计入供冷台数，但群控不得向其写命令；手动机组可能使总台数高于目标。
- 群控 `CoolingCount` 是本次扫描入口观测，`CommittedCount` 是动作前统计；显示可能有一周期延迟。`DemandShortfall` 仅在有效调度路径更新，调用方应结合有效性显示，不能把早退时默认 FALSE 当作“供冷正常”。
- 单机发生停机超时保留尚未撤销的水路/泵请求并报警，不强行关闭冷机水路；实际安全动作仍以厂家要求和正式 SOO 为准。
- 未实现泵压差 PID、最小流量旁通调节、TES 充放冷、水锤控制、设备负荷优化、运行中冗余接管、Modbus 通信程序或 HMI。
